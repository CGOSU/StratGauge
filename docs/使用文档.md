# StratGauge 使用文档

> 面向研究人员和本地运维者的可执行说明。所有示例均假设当前目录为 `backend/`，并设置了 `PYTHONPATH=src`。

## 1. 先读这几条边界

- StratGauge 是半自动研究和记录工具，不连接券商，不创建、修改或取消真实订单。
- 当前行情数据只有日线；收盘后产生的信号最早从下一交易日开始处理。
- 通达信负责执行选股公式，StratGauge 只保存导出文件和公式元数据，不解析或执行通达信公式。
- 所有时间点数据都必须区分 `session_date`、`available_at`、`created_at`/`ingested_at` 和调用方的 `as_of`。交易日早于选股日，不代表数据在当时已经公开可用。
- 原始响应、规范化行情、质量报告、公式、批次、人工标签、客观结果、特征和模型工件均按不可变或追加式证据保存；已有文件通常拒绝覆盖。
- 未成交、数据不足和未解决不等于亏损；统计和训练准入不会把它们静默填成零收益。

## 2. 快速开始

### 2.0 一键启动前后端

完成依赖安装后，推荐从仓库根目录运行统一启动器：

```bash
uv run --project backend python start.py
```

Windows 可双击根目录的 `start.cmd`。启动器并发运行后端和前端，日志分别带 `[backend]`、`[frontend]` 前缀；默认地址为 `http://127.0.0.1:8000` 和 `http://localhost:5173`。按 `Ctrl+C` 或关闭控制台时会清理 Uvicorn reload、pnpm、Vite 及其子进程；任一服务启动/运行失败时会停止另一个服务并返回非零退出码。启动器只编排已有命令，不自动安装依赖、不自动打开浏览器。

常见失败：`uv`、Corepack/pnpm 或前端 `node_modules` 缺失时，请先按下面的安装步骤补齐；后端若出现 `No module named 'stratgauge'`，请使用带 `--app-dir src` 的命令。需要单独排错时，分别启动后端和前端：

```bash
# backend/
uv run uvicorn stratgauge.api.app:app --reload --app-dir src

# frontend/
corepack pnpm dev
```

### 2.1 安装后端

```bash
cd backend
uv sync --all-groups
```

默认依赖包含 FastAPI、DuckDB、Polars、Pydantic、Uvicorn；`live-data` 才安装 AKShare/BaoStock，`ml` 才安装 LightGBM：

```bash
uv sync --extra live-data
uv sync --extra ml
```

默认测试不访问网络。启动 API：

```bash
uv run uvicorn stratgauge.api.app:app --reload --app-dir src
```

### 2.2 启动前端

```bash
cd frontend
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

当前前端默认把 `/api` 代理到本地 API；也可以设置 `VITE_API_BASE_URL` 指向一个完整 API 前缀。前端日期时间控件使用浏览器本地值 `YYYY-MM-DDTHH:mm`，提交时固定补成 `YYYY-MM-DDTHH:mm:00+08:00`。

### 2.3 环境变量

| 变量 | 何时需要 | 作用 |
| --- | --- | --- |
| `TUSHARE_TOKEN` | Tushare 日线、复权因子、股票主数据、Tushare 交易日历 | 只从环境读取，不写入请求快照、日志或文档。 |
| `WAIZAO_TOKEN` | 选择 `waizao` 作为单票日线源 | 只从环境读取；歪枣网当前按证券代码逐票请求。 |
| `VITE_API_BASE_URL` | 前端 API 不在 `/api` 代理下时 | 前端请求的 API 前缀；末尾 `/` 会被移除。 |

## 3. 时间、代码和数字输入约定

### 3.1 日期与日期时间

- `date`：严格使用 `YYYY-MM-DD`，例如 `2026-08-10`。
- 带时区的 `datetime`：使用 ISO-8601，例如 `2026-08-10T17:00:00+08:00` 或 `2026-08-10T09:00:00Z`。后端拒绝无时区的时间。
- 前端的 `datetime-local` 不是带时区的字符串；浏览器表单值会由前端按北京时间追加 `+08:00`。
- `--as-of`、`--exported-at`、`--imported-at`、`--recorded-at`、`--evaluated-at`、`--labeled-at`、`--changed-at`、`--registered-at`、`--compared-at`、`--scored-at` 和 API 中相应字段都必须带时区。
- 交易日历文件中的日期必须唯一、升序排列；空行和 `#` 后的注释会被忽略。

### 3.2 证券代码

- 内部标准标识是 `六位代码.交易所`，交易所只能是 `SH`、`SZ` 或 `BJ`，例如 `000001.SZ`。
- 普通六位代码不允许靠前缀猜交易所；CSV/TSV/TXT 必须有交易所列、代码后缀，或使用通达信固定行情表格式。
- `.EBK` 使用七位市场前缀：首位 `0`=SZ、`1`=SH、`2`=BJ，后六位为代码，例如 `1600593` 解析为 `600593.SH`。
- 通达信行情表在没有交易所列且第一列为代码、同时包含版本化名称表头（如 `名称(4)`、`名称(5)`）和 `涨幅%` 表头时，按首位命名空间映射：`0/3`=SZ、`6`=SH、`4/8`=BJ。普通表格仍不能仅凭六位代码推断交易所。

### 3.3 Decimal、整数和重复参数

- 金额、价格、覆盖率等 Decimal 输入必须是有限数字；金额和价格通常要求大于 0。
- “正整数”不接受小数；重试次数允许 `0`。
- CLI 中标记“可重复”的参数使用 `action=append`，每次出现都会追加一项；例如多个 `--benchmark` 或 `--symbol`。
- API 请求模型使用 `extra="forbid"`，多传字段会被拒绝，不会静默忽略。

## 4. 行情源：什么时候联网，什么时候读本地

这是本项目最重要的操作规则。所谓“写入本地快照”不等于“下一次一定从本地读取”；是否联网由调用入口决定。

### 4.1 总体决策表

| 操作 | 默认数据入口 | 命中本地条件 | 命中后行为 | 未命中时行为 |
| --- | --- | --- | --- | --- |
| `sync_tushare_calendar.py` | Tushare `trade_cal` | 请求区间完整落在已有 calendar manifest 的覆盖区间内，且文本和 manifest 哈希有效 | 读取本地交易日文件，不调用 Tushare | 只请求覆盖区间外的左/右缺口，合并后原子写入文件和 manifest |
| `sync_backup_calendar.py` | BaoStock + AKShare | 同上 | 读取本地双源校验后的日历，不调用两个供应商 | 对每个外部缺口同时请求 BaoStock 和 AKShare；集合不一致则保留原始证据但不发布缓存 |
| `sync_tushare_universe.py` | Tushare `stock_basic` | 没有“自动按请求复用”的跳过分支 | 不适用；每次运行都会调用所选状态的 `stock_basic` | 远程请求 `L` 或 `L/D/P`，内容相同的参考快照在存储层按内容 ID 复用 |
| `sync_tushare_daily.py` | Tushare `daily(trade_date=...)` | 存在同一 provider、交易日、已批准 universe snapshot 的 `market_daily` 快照 | 读取已批准全市场 Parquet；该日不再请求 `daily` | 远程请求全市场日线，通过质量门后写入 raw/Parquet/manifest |
| `sync_tushare_daily.py` 的复权阶段 | Tushare `adj_factor` | 同日市场日线刚通过质量门，并且同 provider、同交易日、同股票池、同 source daily snapshot 的因子快照已批准 | 读取已批准因子快照 | 远程请求 `adj_factor`；日线快照未批准时不会请求因子 |
| `backfill_tushare_adjustment_factors.py` | Tushare `adj_factor` | 已存在匹配的批准因子快照 | 本地跳过 | 只有存在同 provider、同交易日、同股票池的批准 market daily 快照时才远程请求；缺日线只记录 `missing_daily_snapshot`，绝不补抓日线 |
| `mature_tdx_selection.py` | 选定 provider 的单票日线 | 无本地预查 | 不适用；每个候选都调用适配器 | 逐候选远程请求 `start=选股日+1` 到 `end=evaluated_at.date()` 的日线，再把结果写入本地快照 |
| `backfill_selection_history.py` | 选定 provider 的单票历史日线 | 仅交易日历可以从本地读；行情快照没有预查复用分支 | 读取本地 sessions 文件/日历缓存，行情仍请求 provider | 逐候选、基准、行业标的远程请求选股日前的回看区间 |
| Web `POST /v1/selection-batches/{id}/mature` | 选定 provider 的单票日线 | 无本地预查 | 不适用；同步调用 provider | 远程逐候选抓取，结果写入本地 |
| Web 成熟任务 `market_data_mode=provider` | 任务中的 provider | 无本地预查；任务内已有候选结果只按 task/candidate 复用 | 已写入的同任务结果本地复用 | 远程逐候选抓取；网络/限流/超时失败可按 `max_retries` 重试 |
| Web/CLI 成熟任务 `market_data_mode=approved_snapshots` | 已批准全市场快照 | 任务固定保存 `input_market_snapshot_ids` | 只读本地 Parquet 和任务账本，执行不创建 provider 请求 | 缺快照、快照未批准、不可用或股票池不匹配时失败，不回退到 provider |
| API 查询、标签、统计、导出、组合、策略、模型和漂移报告 | 本地 JSON/Parquet/DuckDB | 始终是本地存储 | 不联网 | 缺文件或状态不满足时返回结构化错误 |

### 4.2 交易日历缓存的精确规则

缓存由文本文件和同目录 manifest 组成，例如：

```text
data/calendars/trade-cal-sse.txt
data/calendars/trade-cal-sse.manifest.json
```

缓存读取前会同时检查：文件存在、manifest 可解析、文件日期与 manifest 的 `sessions` 完全一致、日期升序且无重复、内容哈希一致、交易所一致。任何检查失败都是错误，不会用自然日、当前日期或另一个交易所静默替代。

覆盖判断只比较 manifest 的 `start_date` 和 `end_date`。请求范围完全落在边界内时不访问网络；超出左边界或右边界时只拉取外部缺口。当前实现不会用供应商请求去修补覆盖区间内部的“理论缺失日”，因为 manifest 已把现有 session 集合作为缓存事实；如需重新核验完整历史，应删除/迁移到新输出路径后显式重建，并保留旧证据。

Tushare 日历的 `source_providers` 是 `tushare`；备用日历的 `source_providers` 必须包含 `baostock` 和 `akshare`，两个来源的完整交易日集合必须完全一致后才发布。备用缓存不能冒充 Tushare `trade_cal`。

### 4.3 日线快照的精确规则

全市场同步使用以下联合键查找已批准快照：

```text
(provider, session_date, universe_snapshot_id, request_kind=market_daily)
```

命中才返回 `skipped=true` 并读取本地 manifest/Parquet。若快照是 `rejected`、股票池不同、provider 不同、请求日不同或只存在 raw 文件但没有批准 manifest，都视为未命中，需要重新执行 provider 请求。

单票 `ingest()` 当前是“适配器优先”：先调用 `adapter.fetch_daily_bars()`，再将返回内容按 SHA-256 写入快照。相同响应可能生成相同的本地 snapshot ID，但这不会阻止本次远程请求。因此“本地已保存过单票历史”不能推导出成熟或历史补数会离线运行。

### 4.4 快照重放与 provider 模式的区别

`queue_selection_maturity_tasks.py` 只扫描本地已批准的全市场行情，要求从选股日之后到 `now.date()` 至少有 `horizon_sessions + 1` 个连续输入交易日，并创建带固定快照 ID 的任务。`run_selection_maturity_tasks.py` 执行这类任务时调用 `run_selection_outcome_snapshot_job()`：只读本地 Parquet，拒绝供应商调用、未来快照、未批准快照、混用股票池或缺少日期的快照。

相反，Web 页面直接创建的成熟任务默认是 `market_data_mode=provider`。它保存的是 provider、评估时间和政策，不保存全市场输入 snapshot ID；执行时会远程逐候选抓取。要实现可复现的离线重放，必须先完成全市场同步、用队列创建 `approved_snapshots` 任务，再运行任务。

## 6. 推荐的半手动选股流程

### 6.1 先登记公式

通达信公式目录使用 API `POST /v1/formulas` 创建，或在 Web 数据管理页创建。`register_strategy.py` 登记的是策略版本，不是公式目录。推荐先创建公式，这样导入时可以使用不可变的 `formula_id`。

最小公式请求体：

```json
{
  "name": "我的选股公式",
  "version": "v1",
  "description": "可选的公式说明"
}
```

若还需要登记可供回测/模型引用的策略版本，另行执行：

```bash
PYTHONPATH=src uv run python scripts/register_strategy.py --root data --input strategy.json
```

### 6.2 导入通达信文件

```bash
PYTHONPATH=src uv run python scripts/import_tdx_selection.py \
  --file path/to/selection.txt \
  --selection-date 2026-08-10 \
  --exported-at 2026-08-10T15:05:00+08:00 \
  --formula-name "趋势选股" \
  --formula-version v1 \
  --root data/selection
```

导入时会：读取完整文件字节、计算源文件 SHA-256、按格式解析候选、生成批次 ID、保存 raw 文件、解析 JSON 和 manifest。`--imported-at` 默认当前 UTC 时间；它不能早于 `--exported-at`。导入不会联网，也不会请求行情。

### 6.3 在冻结时间内人工标注

```bash
PYTHONPATH=src uv run python scripts/label_tdx_selection.py \
  --root data/selection \
  --batch-id <batch_id> \
  --candidate-id <candidate_id> \
  --decision watch \
  --labeled-at 2026-08-10T15:10:00+08:00 \
  --note "等待次日确认"
```

`--decision` 只能是 `buy_candidate`、`watch`、`pass`、`invalid`。前端按钮显示为“候选”“观察”“放弃”“无效”，其中“候选”表示下一交易日优先复核，不代表已经成交；“观察”表示暂时不买、继续跟踪。标签必须不早于导出时间，且严格早于“选股日期次日 00:00:00（使用导出时间的时区）”；标签只是当时的人工判断，不是行情胜负或实际成交记录。若第二天没有买、之后才实际买入，应在持仓台账记录真实订单/成交时间和价格，不能用原始标签替代成交记录。

#### Web 可复用标签

研究工作台的“新增人工评审”对话框按固定的 `position`（位置）、`pattern`（形态）、`price_volume`（量价）、`sector`（板块）四类展示当前启用的可复用标签。每类输入标签名称后点击“新建并选中”，或在输入框按 Enter，服务端创建标签并立即选中；提交评审时前端只发送 `reusable_tag_ids`，服务端按当前活跃目录生成不可变的 `tag_id/category/label` 历史快照。

数据管理工作区的“可复用标签”目录支持改名、归档和恢复。归档标签不会出现在新的评审选项中，但已有评审仍保留其快照；改名也不会改写历史评审。标签目录和事件追加保存、禁止硬删除。可复用标签当前仅供人工评审和历史展示，不进入 `selection-annotation-dataset-v1`、特征、训练、模型注册、shadow、推荐或交易；若未来用于机器学习，必须另行冻结映射和版本。

### 6.4 选择成熟方式

直接成熟一个批次：

```bash
PYTHONPATH=src uv run python scripts/mature_tdx_selection.py \
  --root data/selection \
  --market-root data/selection-market \
  --batch-id <batch_id> \
  --provider tushare \
  --evaluated-at 2026-08-25T17:00:00+08:00 \
  --horizon-sessions 10 \
  --position-notional 10000
```

这条命令是 provider 模式，会逐候选远程请求日线；`evaluated_at` 必须晚于选股日期。`position-notional` 是费用和收益率计算的名义金额，不能省略或让系统猜测。

若已同步全市场日线，优先使用本地快照重放：

```bash
PYTHONPATH=src uv run python scripts/queue_selection_maturity_tasks.py \
  --root data/selection \
  --market-root data/market \
  --calendar-file data/calendars/trade-cal-sse.txt \
  --provider tushare \
  --horizon-sessions 10 \
  --position-notional 10000 \
  --universe-snapshot-id <universe_snapshot_id>

PYTHONPATH=src uv run python scripts/run_selection_maturity_tasks.py \
  --root data/selection \
  --market-root data/market \
  --limit 1
```

队列命令不联网；它只使用已经批准、同一 provider 和股票池下的全市场快照。`run_selection_maturity_tasks.py --task-id <task_id>` 可以只运行一条指定任务；不传 `--task-id` 时按排队状态取最多 `--limit` 条。

## 7. CLI 完整输入参考

下表覆盖 `backend/scripts/` 当前所有脚本的 argparse 输入。没有列出的参数不存在；脚本不支持通过未知参数扩展行为。运行任一脚本加 `--help` 可获得 argparse 原文帮助。

### 7.1 选股导入、标签、成熟和数据集

#### `import_tdx_selection.py`

| 输入 | 必填/默认 | 类型和约束 | 作用 |
| --- | --- | --- | --- |
| `--file` | 必填 | 文件路径，必须是普通文件 | 要解析的原始导出文件；导入前完整读取字节 |

## 8. HTTP API 完整输入参考

### 8.1 健康、股票和主数据

### 8.2 手工持仓台账

| 方法和路径 | 输入 | 行为 |
| --- | --- | --- |
| `GET /v1/positions` | 无 | 读取由成交重放推导的持仓 |
| `GET /v1/manual-orders` | 无 | 读取本地追加式订单 |
| `GET /v1/manual-fills` | 无 | 读取本地追加式成交 |
| `GET /v1/portfolio-reviews` | 无 | 读取本地追加式复盘 |
| `POST /v1/manual-orders` | `ManualOrderRequest` | 只保存意图，不发送券商 |
| `POST /v1/manual-fills` | `ManualFillRequest` | 记录人工确认成交并重新推导持仓 |
| `POST /v1/selection-candidate-trades` | `CandidateTradeRequest` | 校验候选证券后，原子写入候选关联买入订单和成交 |
| `POST /v1/portfolio-reviews` | `PortfolioReviewRequest` | 记录人工复盘 |

`ManualOrderRequest`：`order_id` 必填非空；`local_code` 必须六位数字；`exchange` 为 `SH/SZ/BJ`；`name` 可选；`side` 为 `buy/sell`；`ordered_at` 必须带时区；`quantity` 为有限正 Decimal；`limit_price` 可选且为正；`strategy_version_id`、`recommendation_id`、`note` 可选。重复/非法 ID 或卖出超过持仓等错误返回 `PORTFOLIO_ORDER_REJECTED`。

`ManualFillRequest`：`fill_id`、`order_id` 必填非空；`filled_at` 带时区；`quantity`、`price` 为有限正 Decimal；`commission` 和 `stamp_duty` 可选，默认 `0` 且不得为负；`note` 可选。成交必须关联可接受订单，错误返回 `PORTFOLIO_FILL_REJECTED`。

`PortfolioReviewRequest`：`review_id` 必填非空；`symbol` 必须为合法 `CODE.EXCHANGE`；`reviewed_at` 带时区；`note` 必填非空；`recommendation_id` 可选。

### 8.3 公式、通达信批次和候选

`POST /v1/formulas` 的 JSON：

```json
{
  "name": "趋势选股",
  "version": "v1",
  "description": "收盘后趋势条件"
}
```

`name` 必填非空；`version`、`description` 可选。公式 ID 按名称和版本内容生成；编辑必须创建新版本，不原地修改。

`POST /v1/selection-batches` 的 JSON：

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `content_base64` | 是 | 有效 Base64；解码后是 UTF-8/GB18030 的 TDX 导出 |
| `selection_date` | 是 | 日期 |
| `exported_at` | 是 | 带时区 datetime |
| `source_filename` | 否 | 只能是文件名，不能含 `/`、`\`、换行或 NUL |
| `formula_id` | 条件必填 | 与 `formula_name` 二选一；传 ID 时必须是启用公式 |
| `formula_name` | 条件必填 | 未传 `formula_id` 时必填 |
| `formula_version` | 否 | 未传 `formula_id` 时作为批次元数据 |
| `formula_sha256` | 否 | 64 位十六进制 |

API 导入时 `imported_at` 由服务器取当前 UTC，不接收调用方传入；API 不联网。

`POST /v1/selection-batches/manual` 的 JSON：`selection_date`、带时区的 `recorded_at`、启用的 `formula_id`、非空 `candidates` 数组。每个候选字段为 `local_code`（恰好六位数字）、`exchange`（`SH/SZ/BJ`）、可选 `name`、可选 `note`。重复的代码+交易所会被拒绝；至少一条候选才能创建。

`POST /v1/selection-batches/{batch_id}/labels` 的 JSON：`candidate_id`、`decision`（四种旧版枚举）、带时区 `labeled_at`、可选 `note`。该接口只用于兼容旧证据。

`POST /v1/selection-batches/{batch_id}/annotations` 的 JSON 必须包含 `candidate_id`、`reviewed_at`、`overall_score`（1—5）、`outlook`（`bullish/neutral/bearish`）和 `decision`（`discard/watch/prepare_buy`）；位置、形态、量价、板块标签可多选，备注可选。每次提交追加一条评审，批次归档后不能新增；评审时间不能早于导出时间。

`POST /v1/selection-batches/{batch_id}/exclusions` 的 JSON 为 `candidate_id`、带时区 `excluded_at` 和必填 `reason`，用于独立记录数据无效，不等同于投资决策。

`GET /v1/selection-observation-pool` 支持 `review_state`（`unreviewed/discarded/watching/preparing`）、`batch_id` 和 `include_excluded` 筛选。

`GET /v1/selection-batches/{batch_id}/candidates/{candidate_id}/analysis` 可选 query `tracking_policy_id`；不传时若历史证据包含多个政策会返回 `TRACKING_POLICY_REQUIRED`。该接口只读本地结果。

### 8.4 成熟任务和行情请求

`SelectionMatureRequest` 用于一次性成熟和创建任务：

| 字段 | 必填/默认 | 约束 |
| --- | --- | --- |
| `provider` | 必填 | `tushare`/`akshare`/`baostock`/`waizao`；不会自动回退 |
| `evaluated_at` | 必填 | 带时区，日期必须晚于选股日 |
| `horizon_sessions` | `10` | 正整数 |
| `position_notional` | 必填 | 有限正 Decimal |
| `target_return` | `null` | 可选非负 Decimal；例如 `0.10` 表示 10%，用于未来表现达标判断 |
| `max_retries` | `2` | 0—5 整数；一次性 `/mature` 不使用此任务重试字段 |
| `timeout_seconds` | `900` | 1—86400；任务 stale 恢复阈值 |

对应接口：

- `POST /v1/selection-batches/{batch_id}/mature`：同步 provider 模式，远程逐候选请求；`max_retries` 和 `timeout_seconds` 被模型接受但一次性调用本身不创建任务重试循环。
- `POST /v1/selection-batches/{batch_id}/maturity-tasks`：本地创建幂等任务；创建本身不请求行情。
- `GET /v1/selection-batches/{batch_id}/maturity-tasks`：本地读取任务列表。
- `POST /v1/maturity-tasks/{task_id}/run`：执行任务；provider 模式远程，approved-snapshots 模式本地。

## 10. 结果、状态和常见误区

### 10.1 成熟结果

当前结果政策默认 ID 为 `outcome-fixed-10-net-positive-v1`，研究基线为：

- 收盘后信号，后续 3 个交易日入场窗口；
- 日线触达是成交近似，开盘成交和最高/最低触达规则由 `entry-limit-chase-v1` 明确记录；
- 固定持有 10 个交易日退出；
- 不启用止盈/止损；
- 扣除费用后净收益大于 0 为 `win`，等于 0 为 `flat`，小于 0 为 `loss`；
- 未触发入场为 `no_entry`，行情不足或质量失败为 `unresolved`；
- 沪深主板数量按 100 股整手向下取整，默认名义金额为 10000 元。

命令行中的 `--horizon-sessions`/API 中的 `horizon_sessions` 可以创建新政策指纹；它不会修改旧结果。

### 10.2 成熟任务状态

`queued` 排队、`running` 执行中、`completed` 全部完成、`partial` 有结果但有拒绝、`failed` 没有可用结果或遇到不可重试失败。只有网络、限流、超时和连接错误被视为可重试；质量门、参数错误、快照冲突和股票池不一致不会自动重试。

### 10.3 不要把这些概念混为一谈

| 误解 | 实际行为 |
| --- | --- |
| “我已经有本地单票 Parquet，所以成熟不会联网。” | 错。provider 模式先调用适配器；只有 approved-snapshots 任务保证离线。 |
| “日历文件存在，所以任何日期请求都不用联网。” | 只有请求范围在 manifest 覆盖边界内才不用联网；缺口会增量拉取。 |
| “同一内容 snapshot ID 相同，所以 provider 没有被调用。” | 错。单票 ingest 可能先远程获取，再因内容相同复用 snapshot 文件。 |
| “全市场快照存在但被拒绝，也能作为缓存。” | 错。只有 `approved` 快照可消费；拒绝快照会导致重新同步或报告阻断。 |
| “复权因子缺失可以顺手抓日线。” | 错。批量因子补齐只消费已批准的同日全市场日线。 |
| “模型分数就是胜率。” | 错。未校准分数不能称胜率；API 固定返回 `authoritative=false`。 |
| “当前股票池可以回答历史日期搜索。” | 错。没有该时点已知快照时返回 `UNIVERSE_SNAPSHOT_NOT_FOUND`。 |

## 11. 排错顺序

1. 先查看命令的 JSON 输出和退出码：`0` 成功，`1` 通常表示质量/准入/比较门未通过，`2` 通常表示输入、provider 或存储错误。
2. 看到“未联网”预期时，检查入口是否为 `approved_snapshots`、是否命中批准快照联合键，以及 calendar manifest 是否覆盖请求区间。
3. 看到 `TUSHARE_TOKEN is not set` 或 `WAIZAO_TOKEN is not set`，先检查当前启动该进程的环境，不要把 token 写进参数或文件。
4. 看到质量拒绝时，先读取对应 `data/**/quality/*.json`，不要直接删除快照重跑；删除会破坏定位，应该使用新的输出或保留原证据。
5. 看到 `UNIVERSE_SNAPSHOT_NOT_FOUND`，先创建与 `as_of`/`known_at` 匹配的时间点股票池，不要将当前股票池复制到历史日期。
6. 看到成熟任务 `queued` 且 `retryable=true`，再次执行任务；如果是 `market_snapshot_quality_rejected`、快照不匹配或参数错误，先修复输入而不是增加重试次数。
7. 看到前端“请求失败”，优先检查 `/healthz`、前端 `VITE_API_BASE_URL`/Vite 代理和后端工作目录；前端不会把错误分数或最新行情填充进页面。
