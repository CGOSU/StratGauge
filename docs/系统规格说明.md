# StratGauge 系统规格说明

> 衡量优势，以证据交易。

本文合并并翻译原 `PRODUCT_SPEC.md`、`ARCHITECTURE.md`、`STRATEGY_SPEC.md`、`DATA_PIPELINE.md`、`BACKTEST_SPEC.md`、`ML_WORKFLOW.md`、`DATA_MODEL.md` 和 `API_SPEC.md`。它是项目实现前的统一产品、架构、数据、策略、回测、机器学习和接口基线。

## 1. 产品定义与边界

StratGauge 是面向单个用户的半自动 A 股决策支持应用：把用户现有的技术选股、买入和卖出流程转化为明确、可测试、可版本化的规则，再结合历史评估和机器学习排序。

系统负责推荐和解释；用户负责确认并手动交易。系统不连接券商、不自动下单，也不承诺收益。

### 目标

- 收盘后扫描 A 股，找出符合策略的股票；
- 按代码或名称查询股票，并获得有证据支持的评估；
- 给出条件式入场区间、失效条件、止损、目标位和持有窗口；
- 查看可比信号的历史表现，而不是无依据的单一分数；
- 手工记录交易，比较用户执行结果与理论策略结果；
- 在不允许系统失控自我修改的前提下改进参数和排序模型。

### v1 包含

- 日线 A 股数据、技术指标和市场状态特征；
- 规则筛选、推荐生成和保守事件回测；
- 手工交易与持仓记录；
- 离线机器学习训练和排序；
- 基于结构化输出的 AI 解释；
- 数据、策略、模型和推荐的完整溯源。

### v1 不包含

- 券商连接、自动下单、分时或高频策略；
- 新闻驱动信号、社会化交易、客户组合和公开付费荐股；
- 保证收益或直接金融承诺；
- 自主修改生产策略。

## 2. 架构

### 2.1 总体方案

初期采用具有明确领域边界的模块化单体：一个后端服务和一个 Web 应用。量化核心使用 Python；未来可使用 Rust 提供 Tauri 桌面外壳或轻量 Axum 网关，但不得复制量化业务规则。

建议目录：

```text
StratGauge/
├── backend/src/stratgauge/
│   ├── api/ domain/ data_sources/ data_pipeline/
│   ├── features/ strategies/ backtest/
│   ├── recommendations/ portfolio/ ml/ jobs/
│   └── tests/
├── frontend/src/ frontend/tests/
├── data/{raw,normalized,features}/
├── artifacts/{backtests,models}/
└── docs/
```

运行数据目录应可配置，通常不进入 Git；仓库只保留小型、确定性的测试夹具。

### 2.2 领域模块

- **市场数据**：数据源适配器、标准标识、标准化行情、复权、证券状态、交易日历和质量报告；
- **特征引擎**：确定性特征及特征集版本，只消费已批准快照；
- **策略引擎**：策略定义、安全表达式、生命周期、资格判断和信号生成，不模拟成交；
- **回测引擎**：订单意图、成交模拟、市场约束、费用、持仓、退出和绩效指标；
- **推荐引擎**：规则、可选模型分数、组合约束和历史队列，生成已发布推荐；
- **组合台账**：手工订单、成交、持仓、跳过、覆写和实际绩效；
- **机器学习**：数据集清单、标签、训练、评估、校准、影子推理和模型注册；
- **解释服务**：把结构化结果转成自然语言，不得修改权威量化记录。

### 2.3 每日流程

1. 确认交易日和股票池；
2. 从主数据源增量获取数据，并按策略从备用源校验；
3. 保存原始响应，标准化为待审核快照；
4. 执行结构、覆盖、连续性和跨源检查；
5. 批准或拒绝快照；
6. 基于已批准快照计算版本化特征；
7. 以收盘时点生成策略信号；
8. 如有激活模型则评分；
9. 为下一个可交易日生成推荐；
10. 更新上一批推荐的结果；
11. 原子发布新的推荐集合。

### 2.4 存储与失败行为

MVP 使用 DuckDB 保存本地分析查询和元数据，用分区 Parquet 保存标准化行情和特征快照；模型注册可使用带数据库配置的本地 MLflow。多设备部署再考虑 PostgreSQL 和对象存储。

FastAPI 提供版本化 `/v1` 接口；长任务返回任务 ID，不长时间占用请求。适配器失败时有限重试并执行备用策略；跨源冲突应隔离，不得静默选值；不完整快照拒绝发布；特征失败时不产生信号；解释失败不影响量化推荐。

默认本地保存用户持仓数据，不保存券商凭据；密钥使用环境变量或批准的密钥机制，日志不得记录完整秘密或不必要的个人数据。

## 3. 数据源与数据管道

### 3.1 数据源策略

AKShare 是免费 A 股日线和辅助数据的主适配器，BaoStock 作为备用和历史交叉校验源。获得权限且质量值得其成本时，可通过同一适配器接口加入 Tushare Pro。策略和特征代码不得依赖某个提供商的列名。交易所和披露网站只用于核实身份、市场规则和公告，不假定其网页是稳定的批量 API。

### 3.2 数据层

- **原始层**：不可变的提供商响应、请求参数、抓取时间、适配器版本和校验和；
- **标准层**：带类型、单位和来源链路的标准数据；修订生成新快照，不抹除旧证据；
- **特征层**：由一份已批准标准快照和一个特征集版本确定性计算。

日线至少包含标准代码、交易日、开高低收、前收、成交量、成交额、来源代码、提供商、适配器版本、事件时间、可用时间、入库时间、质量状态和原始载荷引用。保留未复权行情，复权因子或可复现的复权元数据单独存储。

每个信号日都要保存精确的有效股票集合，防止将当前成分股倒灌到历史日期。

半手动选股允许通达信在系统外执行公式并导出 CSV/TSV/TXT；系统保存原始文件、文件哈希、选股日期、导出时间、公式名称/版本或公式哈希和全部候选。系统不解析或执行通达信公式，也不根据六位代码前缀猜交易所；市场必须来自导出列、代码后缀或用户显式映射。人工标签必须带时区和时间戳，并与客观行情结果分离。

### 3.3 快照与时间点

待审核快照只有在必需检查通过后才能变为 `approved`。允许的状态为 `pending`、`approved`、`rejected`、`superseded`。修订到来时保留旧快照，并以新快照替代它；历史推荐仍引用原快照。

所有数据区分事件发生时间、公开可用时间、系统抓取时间和推荐使用时间。财报和公告只能在实际公开后使用，不能用报告期末日期代替。

每日任务必须幂等；电脑停机后，下一次运行按顺序发现并补处理缺失交易日。

### 3.4 质量检查

- 结构：必填字段、类型、单位、唯一键、时区和日期；
- 价格成交量：价格关系、非负成交量和金额、重复、日历连续性、复权相关跳变和极端波动；
- 覆盖：应有与实收证券数、板块或交易所缺失、异常零成交量、新上市和退市；
- 跨源：收盘价、前收、成交量、成交额、名称、状态及来源新鲜度。

冲突必须记录双方值和解决状态，不得静默覆盖。应监控最近成功交易日、证券数量、隔离行、源响应延迟和错误率、差异率、快照审核时长及推荐新鲜度。

## 4. 数据模型与可复现性

核心实体包括：`security_master`、`trading_session`、`daily_bar`、`adjustment_factor`、`security_status_daily`、`data_snapshot`、`universe_snapshot`、`selection_batch`、`selection_candidate`、`manual_selection_label`、`selection_outcome`、`feature_set_version`、`feature_snapshot`、`strategy_version`、`signal`、`model_version`、`recommendation`、`manual_order`、`manual_fill`、`position`、`recommendation_outcome`、`backtest_run` 和 `data_quality_run`。

`manual_selection_label` 表示用户当时的判断，不等于胜负标签；`selection_outcome` 只能在后续行情成熟后由固定执行政策生成。未入场、过期和未解决样本必须保留，统计时不得强行归入亏损。

快照、版本、运行和推荐使用不透明且不可变 ID；对外使用如 `000001.SZ` 的标准代码，不以可变股票名称作主键。历史数据逻辑唯一性由证券、交易日、提供商和修订共同决定。

每次回测、训练和推荐发布都必须能追溯到：来源快照校验和、标准化版本、股票池快照、特征集、策略、模型与校准版本、市场规则、费用表、代码版本以及相关随机种子。会改变已发布结果的修订不得原地更新，用户交易更正也必须保留审计轨迹。

## 5. 策略规范

策略必须独立支持信号生成和回测，包含：身份说明、数据截止和信号时机、时间点股票池、特征及版本、市场状态、入场资格、触发条件和价格区间、有效期、退出/止损/目标/时间止损、组合与风险约束、歧义和缺失数据处理。

生命周期为：`draft`（草稿）、`validated`（已验证）、`shadow`（影子）、`active`（激活）和 `retired`（退役）。激活和退役需要审计记录；编辑激活策略必须创建新草稿版本。

不得执行任意 Python 表达式。表达式解析为带类型的 AST，仅允许数字、批准的特征、算术、比较、布尔运算以及 `min`、`max`、`abs` 等有限函数。必须拒绝未知特征、循环定义、未声明的除零、非法回看和未来偏移。

信号只表达基于 `as_of` 信息的意图，不代表已经成交。入场意图包括最早和最晚可执行日、触发条件、价格区间、失效条件及风险参数。推荐状态为 `observe`、`wait_entry`、`entry_valid`、`hold`、`reduce`、`exit`，只能由记录的规则和行情推导，不能由 LLM 生成。

## 6. 回测规范

回测只能使用当时可获得的信息，并采用保守的 A 股成交模型。收盘后生成的信号不能在当日成交，最早在下一交易日执行。特征、信号、订单意图和成交时间必须区分，并明确日历及时区。

事件顺序为：开盘、待执行意图生效、检查可交易性、按策略模拟成交、计费和现金变动、按既定优先级评估止损/目标/时间退出、标记持仓、生成下一交易日信号。信号生成与成交模拟必须分离。

成交政策必须显式配置：限价区间、跳空行为、追价上限、订单过期以及同日止损和目标同时触发时的保守处理。不能因为最低价触及限价就假定成交。

有效日期规则表必须覆盖 T+1、板块和风险警示涨跌停、新股例外、停复牌、最小交易单位、复权除权除息、退市和终止持仓。费用包含佣金、最低佣金、印花税或卖方税、过户/清算费和滑点，每次回测保存 `cost_schedule_id`。

回测要防止未来函数、生存者偏差和选择偏差：使用时间点股票池、保留退市证券、使用 `available_at`，并保留用户跳过的全部推荐。输出运行清单、信号及拒绝原因、未成交和成交意图、交易、现金、净值曲线、基准、样本量和不确定性、胜率、盈亏、期望、盈利因子、最大回撤、恢复时长、换手、暴露、集中度及按时间、行业、状态和流动性分组的表现。

必须覆盖的黄金测试包括：收盘后信号不可当日成交、停牌不可成交、无价格交集时过期、跳空超出追价限制时拒绝、T+1 禁止卖出、止损/目标歧义遵循保守策略、最低佣金、有效日期费用切换、公司行为不制造虚假收益、历史退市股不遗漏、历史运行不被修订复权数据悄然改写。

## 7. 机器学习工作流

机器学习只对已通过策略和风险约束的候选进行排序和结果估计，不替代策略引擎，也不能在未声明公式时生成权威入场或退出值。首选 LightGBM 分类器、回归器和排序器，辅以简单市场状态分类或规则特征；深度学习和强化学习暂不纳入范围。

训练样本对应具体 `symbol`、`as_of`、策略版本和特征快照。特征快照不可变，重新计算必须产生新的数据集版本。

标签可包括目标先到、止损先到、限时退出正/负收益、未成交、歧义和未解决；回归目标可包括固定或策略定义期限的净收益、最大有利/不利偏移和持有时长。未成交不能和已成交亏损混为一类。

特征包括趋势、动量、突破距离、波动率、成交量和流动性、横截面排名、基准及行业相对强度、市场广度、状态、策略规则余量，以及后续阶段的时间点估值或公告特征。每项特征都声明回看窗口、可用时间和空值策略。

数据不得按时间随机打乱。使用扩展或滚动的走步验证；同一交易日的证券必须处于同一划分，并通过清除期/隔离期处理标签时间重叠。评估同时看对数损失或 Brier 分数、校准、排序指标、净期望、成交率、成本敏感性、回撤、换手、集中度以及各折和市场状态的稳定性。

树模型原始分数不能直接显示为胜率。必须在按时间排列的验证数据上校准，并在未触碰的测试折评估。界面显示校准估计、历史样本量、不确定性、校准日期和模型版本。Optuna 只能在每个训练折的受限空间内搜索，记录搜索空间、目标、种子、数据清单、环境、选中参数和淘汰试验，禁止反复针对最终测试期优化。

模型生命周期为：不可变数据清单训练挑战者、走步评估、同执行假设比较冠军、注册、影子推理、等待足够成熟的结果、用户明确批准后晋升，并保留回滚。晋升门槛包括足够信号量、净期望改善或不劣、可接受回撤和换手、无灾难性折/状态崩溃、可接受校准、特征稳定以及影子运行成功。

实际交易单独分析，不替代无偏的推荐结果数据。应分别统计策略结果、已发布推荐结果、用户实际执行结果和人工覆写影响。LLM 可解释结构化输出、总结失败集群、起草待审核策略和实验叙述，但不得捏造概率/价格、使用未来结果训练、改变激活策略/模型、隐藏证据不足或把相关性说成因果关系。

## 8. 用户功能与验收

### 功能模块

- **半手动选股**：导入通达信导出批次、查看候选、记录人工标签、跟踪后续行情并生成客观结果；导入和标签不连接券商、不触发自动交易。
- **每日推荐**：数据截止、市场状态、候选排名、匹配状态、入场区间、止损、目标、持有期、样本量、样本外胜率及版本；质量门未通过时不发布。
- **股票查询**：身份、板块、交易状态、最新行情和新鲜度、资格及失败条件、透明组件分数、入场/持有/退出状态、历史统计和风险。
- **策略工作台**：创建、校验、回测、比较、生命周期管理和回滚。
- **回测实验室**：选择时间、时间点股票池、基准、费用、滑点和歧义政策，查看交易和净值，并导出可复现清单。
- **手工交易台账**：记录订单和成交、成本、止损目标、与推荐的偏差、跳过/修改原因，并分离实际和模拟结果。
- **模型运营**：查看实验、比较冠军/挑战者、影子运行、手工晋升/回滚及漂移/校准报告。
- **AI 助手**：只能调用结构化服务并引用时间戳和版本，不得臆造量化值。

### 胜率定义

必须分别展示：所有理论信号胜率、可成交信号胜率、已发布推荐结果率、用户实际交易胜率和当前候选的模型概率。胜率按扣除费用后的收益或明确屏障标签定义，并展示样本量、评估期间和队列定义；小样本显示“证据不足”，不显示虚假的精确百分比。

### MVP 验收

用户能够：更新已验证的日线数据；按指定日期查询股票；运行无未来泄漏的版本化策略；获得下一交易日条件式推荐；查看历史队列、样本量和风险；记录手工成交并比较实际与理论结果；使用保存的版本重新生成同一推荐。

## 9. HTTP API

稳定接口统一使用 `/v1`，URL 和响应使用标准代码；依赖市场的数据必须返回 `as_of`、新鲜度和溯源标识；长任务返回 `202 Accepted` 和任务 ID；可能重复提交的变更接口接受幂等键；错误必须结构化，不能静默降级权威值。

主要接口：

- `GET /v1/stocks/search?q=`：按代码或名称搜索；
- `GET /v1/stocks/{symbol}/analysis?as_of=YYYY-MM-DD`：股票分析；
- `GET /v1/recommendations?trade_date=YYYY-MM-DD`：推荐集合；
- `GET /v1/recommendations/{recommendation_id}`：单条推荐及结果；
- `POST /v1/strategies`、`POST /v1/strategies/{strategy_version_id}/validate`：创建和校验策略；
- `POST /v1/backtests`、`GET /v1/backtests/{run_id}`：提交和查询回测；
- `GET /v1/positions`、`POST /v1/manual-orders`、`POST /v1/manual-fills`：手工组合；
- `POST /v1/recommendations/{id}/decision`：记录接受、跳过或修改，绝不下单；
- `POST /v1/models/train`、`GET /v1/models/{model_version_id}`：训练和查询模型；
- `POST /v1/models/{model_version_id}/promote`、`POST /v1/models/{model_version_id}/rollback`：晋升和回滚；
- `POST /v1/data/jobs/daily-update`、`GET /v1/data/snapshots/latest`、`GET /v1/data-quality/{run_id}`：数据作业；
- `GET /v1/selection-batches`、`POST /v1/selection-batches`：列出和导入通达信选股批次；导入请求使用 Base64 JSON 传递原始文件；
- `GET /v1/selection-batches/{batch_id}`：查看候选、历史人工标签和客观结果历史；
- `GET /v1/selection-batches/{batch_id}/stats`：查看按候选/追踪政策取最新结果后的描述性统计和待成熟数量；
- `POST /v1/selection-batches/{batch_id}/mature`：由 Web 显式选择 AKShare/BaoStock/歪枣网、评估时间、持有期和名义金额，执行一次行情成熟任务；
- `POST /v1/selection-batches/{batch_id}/labels`：追加人工标注，必须在导出后、下一自然日开始前完成，绝不触发交易；
- `GET /v1/jobs/{job_id}`：查询长任务。

统一错误格式示例：

```json
{
  "error": {
    "code": "DATA_SNAPSHOT_NOT_APPROVED",

    "details": {"snapshot_id": "...", "quality_run_id": "..."}
  }
}
```

失败或不可用的概率不得替换为零，过期价格不得替换为无关的最新价格。

## 10. 交付路线

- **阶段 0：基础**：仓库、领域模型、数据适配器、快照、质量门、安全策略 AST、下一交易日回测、股票分析接口和黄金测试。
- **阶段 1：可靠研究系统**：历史补数、时间点股票池、特征版本、策略生命周期、回测报告、市场规则和费用表。
- **阶段 2：每日助手与手工组合**：每日扫描、原子推荐、股票查询、订单/成交/持仓、实际与理论对比和数据健康界面。
- **阶段 3：机器学习排序**：不可变训练清单、标签、LightGBM 基线、清除期走步验证、校准、MLflow、冠军/挑战者和回滚。
- **阶段 4：AI 解释与封装**：结构化解释、策略草稿、失败集群总结、公告摘要和可选 Tauri 封装。

v1 发布前必须满足：每日更新幂等可恢复、质量失败阻止发布、推荐可复现、无收盘后信号当日成交、使用时间点股票池、历史/推荐/实际结果分离、胜率经过校准并带样本信息、模型晋升/回滚可审计，且不存在券商或自动下单能力。

后续可选方向：财报与估值特征、公告 NLP、组合优化、多设备 PostgreSQL、券商 CSV 导入和经单独批准的分钟数据研究。
