# 设计决策

本文件记录已经确认且会影响后续实现的决定。临时想法和普通操作记录不写入此处。

## 记录格式

每项决策应包含日期、决定、原因和约束。如果后续改变决定，应注明被替代条目，而不是删除历史。

## 已确认决策

### 2026-08-09：本地存储采用 DuckDB 与不可变文件混合方案

- 决定：使用 DuckDB 保存快照索引、质量结果、状态及后续回测查询元数据；原始提供商响应保存为内容寻址 JSON，标准化日线保存为内容寻址 Parquet，并由 DuckDB 直接查询。
- 原因：DuckDB 适合单用户本地分析和 Parquet 查询，同时文件快照更便于校验、复现和保留原始证据；无需为阶段 0 引入独立数据库服务。
- 约束：运行数据不进入 Git；原始证据不得只保存在数据库中；避免在 DuckDB 和 Parquet 中重复保存整份行情；当前按单写者设计，出现多设备或并发写入需求后再评估 PostgreSQL。

### 2026-08-09：真实数据源依赖保持可选

- 决定：AKShare 和 BaoStock 放入 `live-data` 可选依赖组；默认安装和自动测试不加载 provider，也不访问外网；真实抓取通过 `backend/scripts/verify_live_adapters.py` 显式执行。
- 原因：阶段 0 的默认验证必须可离线、可复现，同时保留主源、备用源和交叉校验的真实验证入口。
- 约束：真实验证失败不得转化为推荐发布；当前环境中 BaoStock 已通过有限区间质量门，AKShare 受代理连接失败影响，不能宣称双源验证完成。

### 2026-08-09：efinance 不作为独立主备数据源

- 决定：暂不把 `efinance` 作为 AKShare 或 BaoStock 的独立数据源；如后续接入，只能作为同一 Eastmoney 来源的独立客户端适配器，并保留来源标识和交叉验证限制。
- 原因：仓库代码显示其历史 K 线直接请求 `https://push2his.eastmoney.com/api/qt/stock/kline/get`，与本次 AKShare 失败的 Eastmoney 接口相同；实测 `efinance 0.5.9` 也因同一代理连接失败。它能替换调用封装，不能增加数据源独立性。
- 约束：必须显式使用日线 `klt=101` 和不复权 `fqt=0`；不能依赖名称搜索或默认前复权；README 的“不得用于商业用途”与 LICENSE 的 MIT 授权存在表述冲突，商业使用前需确认。

### 2026-08-09：歪枣网仅作为待验证候选数据源

- 决定：不立即接入歪枣网；可在取得 API 凭证和样例响应后，将其作为候选日线恢复源进行小范围验证，但不能直接替代 AKShare/BaoStock 或作为独立交叉校验源。
- 原因：公开文档显示其支持 A 股日线、周线、月线和盘后更新，但未明确底层数据来源、修订规则、质量指标、SLA、停牌语义和商业授权边界；服务依赖 Token、积分/订阅和个人站点运营。
- 约束：StratGauge 只使用其日线收盘后接口；必须保存原始响应、记录供应商版本/抓取时间，并用固定区间与 BaoStock 比较日期、OHLCV、复权口径和缺失日；在验证完成前不得用于推荐发布。
- 安全限制：官方 `waizao` SDK 的 `getDayKLine` 使用 `http://api.waizaowang.com/doc/getDayKLine`，并将 Token 放入 URL 查询参数；在供应商提供 HTTPS 或等价安全鉴权前，不通过该接口发送真实 Token。

### 2026-08-09：临时启用歪枣网单票日线

- 替代前项的范围：用户明确要求临时使用后，允许通过 `WAIZAO_TOKEN` 环境变量调用歪枣网单票日线；不允许把 Token 写入代码、日志、快照 URL 或提交。
- 实现：使用 POST 请求体调用 `getDayKLine`，固定 A 股 `type=1`、日线 `ktype=101`、不复权 `fq=0`；供应商 `cjl` 按手返回，标准层转换为股，原始记录保留原值。
- 验证：000001.SZ 在 2024-01-02—2024-01-05 返回 4 行并通过自身质量门；`code=all` 被服务端拒绝，提示全量查询仅对订阅服务用户开放；与 BaoStock 的价格一致，成交量/成交额差异来自手数转换和供应商取整。
- 后续修正：比较器对成交量和成交额增加 0.001% 相对容差，价格仍使用绝对 0.01 容差；歪枣网适配器升为 `0.2` 以使标准化单位变化生成新快照身份。修正后该固定区间的单票主备交叉校验通过。
- 约束：歪枣网只作为临时恢复源，不改变 AKShare/BaoStock 阶段 0 主备退出条件；接口仅 HTTP，Token 使用完应撤销或更换。

### 2026-08-09：新增通达信半手动选股闭环

- 决定：暂缓继续扩展外部行情平台，新增“通达信导出 → 系统人工标注 → 后续行情跟踪 → 自动结果/统计/机器学习”的半手动方案；通达信负责执行公式，StratGauge 不解析或执行通达信公式。
- 设计：导出的原始文件按内容寻址保存；导入批次记录选股日期、导出时间、公式名称/版本或哈希、文件哈希和导入人；候选股票全部保留，人工决策与客观行情结果分开存储。
- 时间约束：默认只接受收盘后导入；人工标注必须在首个可执行交易日前冻结；系统使用下一交易日开盘/价格区间、T+1、停牌、费用、止损/目标歧义等既有规则计算结果。
- 机器学习约束：人工标注是决策特征，不直接当作客观胜负标签；结果成熟后才生成标签，按时间切分训练/测试，未成交、过期和未解决不得强行归为输赢。
- 接入：本地 API 通过 Base64 JSON 接收导出文件，避免为阶段 1A 引入 multipart 依赖；前端通过 Vite `/api` 代理访问后端。标签接口只追加保存，不覆盖历史标签。
- 结果：客观结果同样按内容寻址追加保存，候选 API 同时返回标签历史和结果历史；真正的行情读取与成熟任务必须在后续作业中显式注入已批准日线。
- 成熟任务：先提供显式 CLI 而不引入后台调度；每个候选单独请求注入的数据源，行情快照必须通过质量门后才能生成结果；当前固定持有期模型不包含未经确认的止盈止损。
- 数据集：导出每个候选的最新人工标签和每个追踪政策的最新客观结果；没有成熟结果的候选也保留为待定；JSONL 目标文件存在时拒绝覆盖，避免训练证据被原地改写。
- 费用与冻结：固定持有期结果必须记录追踪政策指纹、费用方案和名义金额；最低佣金存在时必须显式提供单笔名义金额，系统不得按一股猜测。标注冻结采用“下一自然日 00:00”保守截止，避免将入场后的人工判断作为特征。
- 通达信导出兼容：`.EBK` 的七位纯文本行按首位市场标记解析：`0` 为深市、`1` 为沪市、`2` 为北市；行情表 `.txt` 仅在识别到通达信 `代码`、`名称(4)`、`涨幅%` 表头时，按其代码命名空间映射 `0/3` 深市、`6` 沪市、`4/8` 北市，并跳过 `#数据来源` 尾行。普通 CSV 仍禁止按代码前缀猜测交易所。
- Web 执行：成熟任务通过 Web 提交一次性显式参数并同步返回结果摘要；不引入后台定时器、自动重试或自动交易，避免在运行环境和幂等策略未冻结前扩大执行面。
- 公式目录：公式名称、版本和说明先通过“新建公式”持久化为不可变目录项，导入批次只提交 `formula_id`；通达信仍负责公式执行，系统不解析公式内容。
- Web 视觉：采用 shadcn/ui 基础组件和浅色语义色变量，使用标题、正文、辅助信息、状态徽章四级层次区分信息重要性；不保留暗色主题。

### 2026-08-10：前端布局和颜色使用项目级 design-system token

- 决定：继续保留浅色主题，在 `frontend/src/styles.css` 集中定义语义颜色、间距、圆角、阴影和层级 token；按钮、卡片、输入框、选择器、提示、徽章和对话框的视觉变体通过语义组件类复用。
- 布局：页面容器使用 1280px 上限和移动优先断点；主要控件保持稳定尺寸和可见 `focus-visible` 状态，窄屏下表单标题区和栅格转为单列。
- 原因：当前页面已经有业务流程和 shadcn/ui 原语，不新增组件库或暗色主题；只收敛现有视觉，避免把研究数据管理页变成装饰性 Dashboard。

### 2026-08-10：新增 Web 数据管理和追加式生命周期

- 决定：Web 增加“数据管理”工作区，统一管理手动创建的公式和导入批次；支持查看批次候选、人工标签、客观结果、生命周期历史和原始文件下载。
- 生命周期：不提供硬删除；停用/归档和恢复均写入不可变的生命周期事件。研究工作台只显示启用公式和批次，管理工作区可筛选全部、启用中和已停用数据。
- 原因：公式、原始导出、人工标注和客观结果都是研究证据，删除或原地修改会破坏复现和审计；用户仍需要隐藏旧版本和重复批次。
- 约束：归档批次只读，禁止继续人工标注或执行成熟任务；恢复后才可继续；归档公式不能用于新导入，但历史批次仍保留其公式引用。

### 2026-08-10：JSONL 数据集通过 Web 即时下载

- 决定：数据管理页直接根据当前不可变存储生成 JSONL 响应并下载，不在服务器额外写入导出文件。
- 原因：避免后台任务、导出文件生命周期和覆盖冲突；现有数据集构建器已经保留待定候选、最新标签、最新政策结果和来源快照链。
- 约束：下载是只读操作；CLI 继续负责需要长期保存的 JSONL 文件，目标存在时仍拒绝覆盖；Web 不改变任何研究证据。

### 2026-08-10：公式编辑采用新版本而非原地覆盖

- 决定：数据管理页提供“编辑为新版本”，修改后通过新公式目录项保存；原公式 ID、名称/版本留痕和历史批次引用保持不变。
- 原因：公式目录是研究证据的一部分，原地修改会让历史批次无法复现；版本化创建已经复用现有公式创建接口。
- 约束：保存新版本时必须修改名称或版本号；仅修改说明不能覆盖原记录。

### 2026-08-10：管理统计使用最新标签和最新政策结果

- 决定：管理页统计接口支持公式版本、来源、选股日期范围、最新人工决策、结果政策和批次生命周期筛选；结果按候选与追踪政策取最新客观结果。
- 原因：管理页需要在不修改研究证据的前提下复核样本覆盖、待定数量、胜率和平均净收益；复用现有最新结果语义，避免重复成熟结果重复计数。
- 约束：统计是描述性汇总，不代表预测承诺；未成熟候选计入待定，未入场和未解决不强行归入输赢。

### 2026-08-10：数据集按选股日期切分且输出不可覆盖 manifest

- 决定：使用显式 `train_end` 和 `validation_end`，按 `selection_date` 将 JSONL 分为 train、validation、test；不随机打乱，不允许分区边界重叠。
- 证据：切分输出保存源 JSONL SHA-256、schema 版本、边界和各分区行数；四个输出文件存在时拒绝覆盖。
- 原因：先冻结无未来信息泄漏的清单规则，再进入机器学习特征和基线模型；当前不引入随机抽样或外部数据集注册服务。

### 2026-08-10：成熟任务使用本地 JSON 账本和显式 CLI

- 替代：本文件前述“先提供显式 CLI 而不引入后台调度”和“Web 同步一次性成熟、不自动重试”的范围决定；一次性同步接口仍保留作为兼容入口。
- 决定：在保留一次性同步成熟接口的基础上，增加成熟任务账本；任务按 `batch_id + UTC evaluated_at + tracking_policy_id + provider` 内容寻址，创建幂等，首次配置不可变。
- 执行：任务状态为排队、执行中、完成、部分完成或失败；每次尝试、重排队和结果均追加事件。任务结果带 `maturity_task_id`，同一任务和候选只允许一个客观结果，重跑复用已有结果。
- 重试：仅网络、限流和超时错误可重试；质量门失败、参数错误、存储错误和响应格式错误不可自动重试；超时运行记录由下一次显式执行恢复。
- 调度：新增显式 CLI `run_selection_maturity_tasks.py`，供 Windows Task Scheduler 调用；不在 Web 进程内注册后台定时器，不引入 Redis/Celery，不连接券商。
- 原因：先获得可恢复、可审计和幂等边界，再决定是否需要独立后台基础设施；单用户本地部署使用操作系统调度足够。

### 2026-08-10：手工候选批次使用规范化 JSON 证据

- 决定：新增手工候选批次入口，保存选股日期、记录时间、公式 ID 以及每个候选的六位代码、显式交易所、名称和备注；手工来源标记为 `manual`。
- 原因：补齐不依赖通达信文件的人工录入路径，同时复用现有批次、候选、标签和结果追踪闭环。
- 证据与幂等：规范化请求按 UTF-8 canonical JSON 保存为原始证据，并由内容生成批次 ID；相同请求重复提交返回同一批次，不覆盖原始文件。
- 约束：普通六位代码不得按前缀猜测交易所；候选不得重复；公式必须存在且启用；仍禁止自动交易、券商连接和分钟/Tick 数据。

### 2026-08-10：机器学习训练前必须通过数据准入审计

- 决定：在特征工程和模型训练前增加显式 `audit_selection_ml_readiness.py`；审计输入必须是 `selection-dataset-v1`，输出源文件 SHA-256、样本统计、政策范围、阻断原因和警告。
- 原因：当前策略参数尚未冻结，且数据集包含待定、未入场和未解决样本；不能让训练脚本静默把不完整结果当作输赢标签。
- 约束：策略参数必须由 CLI 显式声明已冻结；默认至少需要 100 条完成结果，并要求至少两个完成结果状态、单一追踪政策、候选/政策无重复和完整行情快照证据；审计不执行训练，未通过返回非零退出码。样本阈值可通过 CLI 调整，但不能绕过审计结论。

### 2026-08-10：历史特征补数必须使用显式交易日历和批准快照

- 决定：新增 `backfill_selection_history.py`，按选股日前的显式交易日列表截取最长回看窗口；候选自动来自批次，基准和行业标的只能由调用方以明确 `CODE.EXCHANGE` 提供。
- 原因：A 股周末和法定节假日不能用自然日推断；同一证券的缺失交易日、缺失证券、历史窗口不足和质量门失败必须可审计，不能用填充行伪造特征。
- 约束：只把 `approved` 快照 ID 交给后续特征阶段；拒绝快照仍保留为证据但不进入 `approved_snapshot_ids`；当前不自动推断基准或行业归属，也不在本切片实现特征计算。

### 2026-08-10：第一版特征和基线保持确定性、离线和无新增依赖

- 决定：使用内容寻址的 `FeatureSetVersion` 和 `FeatureSnapshot`；第一版只计算收盘价、收益、波动率、成交量/成交额、均线距离、基准收益和相对强弱。输入必须严格早于选股日，且所有输入 `available_at <= as_of`。
- 原因：先冻结可审计的特征契约和未来数据边界，再引入复杂模型；当前历史补数数据可能是事后抓取，不能假装在历史选股时已经可见。
- 约束：缺失窗口、未对齐基准、未来交易日和延迟/修订输入直接阻止特征行生成；`train_selection_baseline.py` 只接受 `selection-feature-dataset-v1`，使用按选股日期切分的常数概率基线，不把概率称为收益保证。

### 2026-08-10：策略生命周期和手工组合均采用追加式本地账本

- 决定：策略版本内容不可覆盖，生命周期通过 `StrategyVersionStore` 事件追加记录；手工订单、成交、复盘记录不可覆盖，持仓由成交重放推导。
- 原因：模型/策略研究证据和用户实际交易必须分离，原地编辑会破坏复现和审计；单用户本地部署暂不引入独立服务。
- 约束：不连接券商、不自动下单；卖出成交不得超过当前推导持仓，成交不得超过订单数量；股票搜索、用户覆写和真实策略参数仍待独立定义。

### 2026-08-10：回测报告只汇总理论证据

- 决定：新增 `backtest/report.py` 和 `report_backtest.py`，输入只能是已有 `BacktestResult`；报告按策略版本、成本政策、显式市场状态和入场日期分组，并使用内容 ID。
- 原因：理论成交、用户推荐和实际手工成交的证据来源不同，不能用一个汇总数字混淆三者；当前已有回测结果契约，复用它比新增报告数据库更简单。
- 约束：市场状态必须由调用方显式提供；缺失状态标记为 `unspecified`，不推断牛熊；报告不代表预测收益或实际交易表现。

### 2026-08-10：股票搜索限定为时间点股票池

- 决定：新增 `/v1/universe/securities`，按带时区的 `as_of` 选择当时已知的最新 `UniverseSnapshot`，再按代码或名称搜索。
- 原因：当前没有完整、版本化的 A 股主数据和历史成分，直接实现全市场搜索会引入未来成分和交易所猜测。
- 约束：无已知快照时返回结构化错误；证券和交易所必须来自显式股票池；不提供自动补齐主数据或用户覆写。

### 2026-08-10：自动股票数据源切换为 Tushare Pro

- 决定：新增 Tushare Pro 适配器，使用 `TUSHARE_TOKEN` 环境变量；`daily` 作为不复权 A 股日线主源，`stock_basic` 生成不可变股票元数据参考快照，`trade_cal` 生成显式交易日历；新增流程默认选择 Tushare，AKShare 保留兼容入口。
- 原因：用户已指定 Tushare Pro 作为自动股票数据源；其接口同时提供日线、股票列表和交易日历，能覆盖行情补数、时间点股票池和特征回看窗口。
- 单位：Tushare `daily.vol` 为手，转换为股；`daily.amount` 为千元，转换为元；原始响应仍保存，标准化层只消费转换后的值。
- 安全与验证：Token 只从环境变量读取，不写入请求快照或错误消息；默认测试注入伪造响应，不访问网络；真实验证必须设置 Token 后显式运行，未验证前不把主源标记为通过。
- 约束：仍只支持 A 股日线和收盘后研究；Tushare 积分、接口权限、限流和数据修订时间必须作为运行风险记录；BaoStock 仍可做备用和固定区间交叉校验。

### 2026-08-10：模型注册和生命周期使用本地不可变工件

- 决定：新增 `ModelRegistryStore`，注册时保存模型 JSON、评估报告和训练 manifest 的内容副本，并在注册清单中记录 SHA-256、特征版本、追踪政策、源数据哈希、随机种子、环境/训练 manifest 哈希和注册操作者。
- 生命周期：新模型从 `challenger` 开始；只能通过追加事件进入 `shadow`、`active` 或 `retired`。激活必须通过人工 `promote`，引用与注册一致的评估报告哈希；同一追踪政策最多一个 active 模型。`rollback` 先退役当前 active，再激活已退役目标模型。
- 原因：模型文件、评估证据和生命周期状态必须可复现且可审计；不能通过覆盖 JSON 或自动晋升改变当前模型。
- 约束：当前实现本地注册、哈希校验、人工生命周期、比较门禁和回滚边界；尚未实现 LightGBM、校准模型、完整走步收益指标和 Web 影子评分。模型分数仍不能称为校准胜率或收益保证。

### 2026-08-10：晋升必须引用显式比较报告

- 决定：新增 `ModelEvaluationEvidence`、`ComparisonPolicy`、`ModelComparisonReport` 和 `compare_selection_models.py`；比较策略由调用方提供，报告逐项保存候选/冠军指标、绝对阈值、相对退化阈值、校准要求、评估哈希、操作者和时间。
- 门禁：缺失指标直接失败；不在代码中为净收益、回撤、换手、信号量、特征稳定性或最差折表现猜测默认值。常数基线仅有 Log Loss/Brier 等已产生指标，使用要求完整运营指标的策略时会被阻断。
- 生命周期：`ModelRegistryStore.promote` 必须引用内容哈希匹配且 `gate_passed=true` 的比较报告；若报告比较了现有 active 模型，必须先人工将该冠军退役，再人工晋升 challenger。报告来自未来、模型/政策/评估哈希不匹配或报告被篡改时拒绝晋升。
- 原因：模型比较和人工晋升是两个不同的证据步骤；把阈值写入代码或自动替换 active 模型会掩盖用户策略偏好和研究假设。

### 2026-08-10：影子评分独立于人工决策和客观结果

- 决定：新增 `shadow.py` 和 `score_selection_shadow.py`，只接受不带结果标签的 `FeatureSnapshot` 输入；评分写入独立 `shadow-scores` 目录，记录模型版本、shadow 生命周期、特征版本、输入快照、追踪政策和评分时间。
- 输出语义：字段命名为 `uncalibrated_model_score`，并固定记录 `calibrated=false`、`used_for_decision=false`；不输出胜率、收益保证或权威推荐。
- 失败边界：单个候选的特征版本不匹配或尚未到评分时间时，只写入独立报告的失败项；模型工件损坏、生命周期不允许或存储完整性错误直接阻止本次影子任务，但不修改原始批次、人工标签、客观结果或成熟任务。
- 约束：当前只支持注册的常数概率基线且只允许 `shadow` 模型；尚未自动接入新导入批次、LightGBM、校准模型、API 或前端。
