# 设计决策

本文件记录已经确认且会影响后续实现的决定。临时想法和普通操作记录不写入此处。

## 记录格式

每项决策应包含日期、决定、原因和约束。如果后续改变决定，应注明被替代条目，而不是删除历史。

## 已确认决策

### 2026-08-20：成熟状态列表只读投影与机器学习前置检查保持同一范围

- 决定：导入数据页在机器学习前置检查之后展示独立的“成熟结果列表”，只调用 `GET /v1/selection-maturity/page`；不恢复成熟任务的 Web 创建/执行入口，也不在请求中启动行情、成熟、训练、评分或交易操作。
- 决定：列表跨全部历史批次读取，包含归档批次和已排除候选；记录按“候选 + tracking policy”保留每个 policy 的最新客观结果。没有任何结果的候选显示为 `pending`（待成熟），`no_entry` 和 `unresolved` 保留为独立状态。
- 决定：列表的 `status_counts` 始终统计全部范围的六类状态，`status` 筛选只影响当前 `items/total`；分页继续使用 `page/page_size/total/has_next`，并沿用既有状态语义色和分页控件。
- 原因：用户需要在不改变事实账本和成熟执行边界的前提下检查历史覆盖。待成熟、未入场和未解决都不是可训练的 `win/loss/flat` 标签，归档与排除证据也必须与 ML readiness 统计保持一致。
- 约束：该投影只读，不改变成熟任务 API、CLI、客观结果持久化格式或影子评分的 `used_for_decision=false` 边界。

### 2026-08-16：前端引入真实 ESLint，TypeScript 固定在 6.x 工具链线

- 决定：新增 `frontend/eslint.config.js`（ESLint 10 flat config + typescript-eslint recommended + react-hooks recommended）；`lint` 脚本从重复的 `tsc` 改为 `eslint .`，类型检查继续由 `typecheck`/`build` 承担。
- 决定：`typescript` 从 7.0.2 降到 `~6.0.3`。TS 7 是原生编译器线，typescript-eslint 硬性拦截 TS 7.0；TS 6.x 是同一语言版本的 JS API 并行线（官方为工具链兼容保留），tsc/Vite/typescript-eslint 共用一条工具链，类型检查语义等价。
- 决定：`react-hooks/set-state-in-effect` 在配置中降级为 `warn` 并注释原因：既有数据加载和表单重置 effect 广泛使用"effect 内同步 setState"模式，行为正确但被新规则反对，待 `App.tsx` 按领域拆分时逐步重构；`rules-of-hooks` 保持 error。
- 决定：删除前端成熟任务死代码（`{false && ...}` 禁用面板、三个任务函数、相关状态/类型/helper，共约 470 行）。这些代码自 2026-08-13 移除成熟操作区后不再有任何调用点；后端成熟任务账本、CLI 和兼容 API 全部保留不动。
- 原因：此前 `lint` 与 `typecheck` 脚本完全相同且无 ESLint 配置，历次"lint 通过"实际只是类型检查；React Hooks 依赖错误和死代码（如 `no-constant-binary-expression` 发现的常量条件 JSX）长期无检查。
- 验证：`corepack pnpm lint` 通过（0 error、21 warning，全部为上述基线 warn 项）；`typecheck`、`build`、`git diff --check` 通过。

### 2026-08-15：IO 优化保持事实文件不变，以可重建投影、分页和显式任务降低读取与执行放大

- 决定：JSON、Parquet、manifest 和追加事件文件继续作为事实/审计来源；DuckDB catalog 与 `SelectionReadIndex` 只保存查询元数据和事实文件路径，可删除后重建，不能替代事实文件。
- 决定：SnapshotStore 的 catalog 快速路径直接构造 manifest；`verify_fast()` 只做存在性和 catalog 健康检查，深度 `verify()` 继续执行文件哈希与 Parquet 校验。Selection 读投影失效时降级全量扫描，不改变字段、排序和错误契约。
- 决定：高基数读取使用新增分页入口，统一 `page/page_size/total/has_next` 且 `page_size <= 200`；旧完整列表和下载路由保留。JSONL Web 下载按记录使用 `StreamingResponse`，不写临时导出文件。
- 决定：主板同步任务使用 `LocalJobStore` 和显式 CLI/API runner，FastAPI 不启动后台线程或定时器；只有 `queued` 可取消。任务内复用一个可关闭 Tushare transport，任务终态后释放连接；任务视图不暴露数据根目录和凭证。
- 原因：减少重复 manifest/JSON 扫描、大结果集整批读取和任务级连接建立，同时不牺牲不可变证据、单写者锁、配额边界和旧 API 兼容性。
- 验证：离线回归断言 catalog 命中不读 manifest、索引读取不触发目录扫描、流式响应类型和任务状态持久化；完整后端 359 项通过、1 项跳过，前端 typecheck/lint/build 通过。

### 2026-08-14：代码整理采用可验证的小步重构，不按“旧”字样删除业务代码

- 决定：第一轮 clean-code 只做行为保持型整理：统一 MyPy 输入和格式基线，抽取 ML 规范 JSON/SHA-256、原子文本写入等已证实重复的底层工具，拆出前端 API 合约、日历输入和主板同步面板边界。
- 决定：只有全仓引用检查确认无消费者的前端 provider/hook 和 `decisionDescription` 被删除；公开 FastAPI/CLI 入口、数据源适配器、历史数据模型和 `legacy-unknown` 等兼容路径不因文件较老或仓内调用较少而删除。
- 原因：CLI 可能由外部调度器调用，历史快照/数据模型需要读取旧证据；先消除重复和职责混杂，再通过测试保障后续拆分，避免把兼容性误判为死代码。
- 约束：后续对 `App.tsx`、`SelectionService` 和 ML 大模块的拆分必须按领域边界分批进行，每批保持 API、CLI、持久化格式和证据 ID 兼容，并完成全量验证。

### 2026-08-14：主板收盘同步以阶段诊断和研究边界呈现失败

- 决定：`POST /v1/market-sync/main-board` 为每个同步 session 返回日线与复权因子阶段诊断，包含状态、覆盖率、预期/实际证券数、质量问题、中文处理建议、快照 ID 和 `quality_run_id`；顶层使用 `research_ready` 表示所有阶段是否都已批准。
- 决定：质量门拒绝继续以 HTTP 200 返回并持久化不可变证据，但必须标记为不可用于研究；供应商、存储、前置条件和未知异常中止同步，使用稳定机器可读 `code`，用户可见的 message/reason/suggestion 使用中文且不暴露凭据。
- 决定：前端同步面板按阶段展示证据与行动建议，完整批准才显示研究就绪；含拒绝 session 时明确提示未批准数据不会进入研究。窄屏将阶段卡片和结果行改为单列/折叠布局，长 ID 允许换行。
- 原因：质量拒绝需要保留证据链以便重试和排查，同时阻止研究工作台误把部分数据当作完整行情；结构化 code 保持 API 集成稳定，中文诊断降低本地运维排错成本。
- 未实施的 Web UX 建议：尚未增加同步诊断的浏览器视觉回归/Storybook 测试、未成交/部分成交的独立前端录入入口、以及对同步阶段的进度轮询或取消操作；本轮不改变同步 API 的同步执行、自动重试和交易确认边界。

### 2026-08-14：旧手工台账默认合并录入已确认订单与成交

- 决定：持仓/交易记录中保留的手工台账入口使用一个“录入订单与成交”表单，通过 `/v1/manual-trades/confirm` 原子写入完整订单和成交；前端自动生成 `order_id` 与 `fill_id`，不要求用户复制 ID。
- 决定：表单只代表已确认的完整成交；卖出必须选择结构化卖出原因。未成交订单和部分成交仍由独立后端 API 保留，不在该默认表单中伪装为已成交。
- 原因：旧的先录订单、再复制订单 ID 录成交流程容易出错，且当前产品主要记录用户已经确认的真实交易；后端已有原子写入和幂等边界，可以复用而不改变账本模型。

### 2026-08-13：桌面研究台优先使用后端只读投影与统一股票详情抽屉

- 决定：前端采用固定左导航、顶部运行状态栏、中央工作区和 420–520px 右侧 `Stock Detail Drawer`；工作台、今日信号、观察池、持仓、交易记录、策略和分析共享同一股票详情入口，低频数据管理进入设置。
- 决定：Daily Signals、Watchlist、Positions、Trades、Strategies 和 Analytics 首先消费 `/v1/workbench/*` 只读投影；前端不从导入文件 `source_fields` 推断现价、行业或技术指标，也不把策略信号直接当作交易。
- 决定：Drawer 的“判断”操作只向既有选股批次追加 `SelectionAnnotation`，保留旧判断、明确“未判断不等于不看好”，行情缺失显示 `unavailable/incomplete`，不补零或伪造 K 线。
- 决定：桌面壳层迁移期间保留现有手工台账录入入口；BUY/SELL 仍必须经过用户显式确认，统一 Drawer 交易生命周期迁移作为后续 `UI-03 portfolio-lifecycle-ui`。
- 原因：先统一信息架构和证据边界，再逐步迁移交易写入和重新评估交互，避免一次性重写旧研究/台账流程造成事实丢失。

### 2026-08-11：仓库根目录统一编排前后端开发服务

- 决定：新增根目录 `start.py` 作为跨平台开发入口，使用 Python 标准库和 `subprocess` 参数数组并发启动后端 `uv run uvicorn stratgauge.api.app:app --reload --app-dir src` 与前端 `corepack pnpm dev`；Windows 提供 `start.cmd` 双击入口。
- 决定：启动器固定服务工作目录和仓库相对路径，转发带 `[backend]`/`[frontend]` 前缀的日志，传播启动/运行失败的非零退出码；不安装依赖、不打开浏览器、不复制 Vite 参数或配置。
- 决定：退出、Ctrl+C 或窗口终止时清理两个服务及其子进程；Windows 使用 Job Object/进程树清理，POSIX 使用独立进程组；后端工作目录保持为 `backend/` 以保留 `backend/data` 默认路径。
- 原因：减少开发者手工开两个终端时的路径和 `src` 导入错误，同时不引入 shell 后台语法或第三方进程管理依赖。

### 2026-08-11：技术规格与使用文档分工，并显式记录行情缓存边界

- 决定：`docs/系统规格说明.md` 只维护当前实现的产品边界、模块职责、数据契约、缓存策略、成熟模式和 API 路由索引；`docs/使用文档.md` 维护可执行命令、每个 CLI/API/UI input 的字段规则和操作排错。
- 决定：使用文档必须把“远程请求被跳过”和“远程响应写入时内容寻址复用”分开描述；单票 provider 模式不因本地存在同范围快照而自动离线，只有全市场批准快照和 `approved_snapshots` 成熟任务保证本地重放。
- 原因：此前说明集中在 README/规格中的命令示例，无法让使用者判断一次操作是否会访问行情源；将判定条件、快照联合键和入口模式写成表格，减少误把本地结果当作网络缓存的风险。

### 2026-08-11：错误提示和日期字段采用统一的前端交互

- 决定：研究、数据管理和持仓工作区的请求错误统一使用可关闭的吸顶提示；错误提示仍保留 `role="alert"`，不改为自动消失的 toast，避免用户在长页面中错过诊断信息。
- 决定：日期和日期时间字段统一通过 `CalendarInput` 包装原生控件，增加明确的日历按钮、可选清空按钮和焦点反馈；浏览器支持 `showPicker()` 时由按钮打开原生选择器，不支持时仍回退到输入框聚焦和原生交互。
- 决定：统计日期起止字段使用 `min`/`max` 互相约束，允许单独留空，不在前端静默改写用户已选日期；不新增日期组件依赖或自定义日历数据源。
- 原因：统一交互可以删除三处重复错误 JSX 和旧日期样式，同时保留原生日期输入的无障碍、键盘和浏览器本地化能力。

### 2026-08-11：文件上传使用可视化选择卡片

- 决定：通达信导入保留真实 `input[type="file"]` 和原有 `accept` 限制，但不直接展示浏览器默认文件框；使用上传卡片承载选择按钮、文件名、文件大小、重新选择和清除操作。
- 决定：文件已选状态使用独立的 selection 语义色，不复用 A 股盈利红；长文件名允许换行，上传卡片在移动端保持容器内布局。
- 原因：原生文件框在不同浏览器中的显示不一致，且未选/已选状态不够明确；视觉层改造不改变文件读取、原始证据保留和提交前校验逻辑。

### 2026-08-09：本地存储采用 DuckDB 与不可变文件混合方案

- 决定：使用 DuckDB 保存快照索引、质量结果、状态及后续回测查询元数据；原始提供商响应保存为内容寻址 JSON，标准化日线保存为内容寻址 Parquet，并由 DuckDB 直接查询。
- 原因：DuckDB 适合单用户本地分析和 Parquet 查询，同时文件快照更便于校验、复现和保留原始证据；无需为阶段 0 引入独立数据库服务。
- 约束：运行数据不进入 Git；原始证据不得只保存在数据库中；避免在 DuckDB 和 Parquet 中重复保存整份行情；当前按单写者设计，出现多设备或并发写入需求后再评估 PostgreSQL。

### 2026-08-09：真实数据源依赖保持可选

- 决定：AKShare 和 BaoStock 放入 `live-data` 可选依赖组；默认安装和自动测试不加载 provider，也不访问外网；真实抓取通过 `backend/scripts/verify_live_adapters.py` 显式执行。
- 原因：阶段 0 的默认验证必须可离线、可复现，同时保留主源、备用源和交叉校验的真实验证入口。
- 约束：真实验证失败不得转化为推荐发布；当前环境中 BaoStock 已通过有限区间质量门，AKShare 受代理连接失败影响，不能宣称双源验证完成。

### 2026-08-09：efinance 不作为独立主备数据源

- 决定：暂不把 `efinance` 作为 AKShare 或 BaoStock 的独立数据源；如后续接入，只能作为同一 Eastmoney 来源的独立客户端适配器，并保留来源标识和交叉验证限制。
- 原因：仓库代码显示其历史 K 线直接请求 `https://push2his.eastmoney.com/api/qt/stock/kline/get`，与本次 AKShare 失败的 Eastmoney 接口相同；实测 `efinance 0.5.9` 也因同一代理连接失败。它能替换调用封装，不能增加数据源独立性。
- 约束：必须显式使用日线 `klt=101` 和不复权 `fqt=0`；不能依赖名称搜索或默认前复权；README 的“不得用于商业用途”与 LICENSE 的 MIT 授权存在表述冲突，商业使用前需确认。

### 2026-08-09：歪枣网仅作为待验证候选数据源

- 决定：不立即接入歪枣网；可在取得 API 凭证和样例响应后，将其作为候选日线恢复源进行小范围验证，但不能直接替代 AKShare/BaoStock 或作为独立交叉校验源。
- 原因：公开文档显示其支持 A 股日线、周线、月线和盘后更新，但未明确底层数据来源、修订规则、质量指标、SLA、停牌语义和商业授权边界；服务依赖 Token、积分/订阅和个人站点运营。
- 约束：StratGauge 只使用其日线收盘后接口；必须保存原始响应、记录供应商版本/抓取时间，并用固定区间与 BaoStock 比较日期、OHLCV、复权口径和缺失日；在验证完成前不得用于推荐发布。
- 安全限制：官方 `waizao` SDK 的 `getDayKLine` 使用 `http://api.waizaowang.com/doc/getDayKLine`，并将 Token 放入 URL 查询参数；在供应商提供 HTTPS 或等价安全鉴权前，不通过该接口发送真实 Token。

### 2026-08-09：临时启用歪枣网单票日线

- 替代前项的范围：用户明确要求临时使用后，允许通过 `WAIZAO_TOKEN` 环境变量调用歪枣网单票日线；不允许把 Token 写入代码、日志、快照 URL 或提交。
- 实现：使用 POST 请求体调用 `getDayKLine`，固定 A 股 `type=1`、日线 `ktype=101`、不复权 `fq=0`；供应商 `cjl` 按手返回，标准层转换为股，原始记录保留原值。
- 验证：000001.SZ 在 2024-01-02—2024-01-05 返回 4 行并通过自身质量门；`code=all` 被服务端拒绝，提示全量查询仅对订阅服务用户开放；与 BaoStock 的价格一致，成交量/成交额差异来自手数转换和供应商取整。
- 后续修正：比较器对成交量和成交额增加 0.001% 相对容差，价格仍使用绝对 0.01 容差；歪枣网适配器升为 `0.2` 以使标准化单位变化生成新快照身份。修正后该固定区间的单票主备交叉校验通过。
- 约束：歪枣网只作为临时恢复源，不改变 AKShare/BaoStock 阶段 0 主备退出条件；接口仅 HTTP，Token 使用完应撤销或更换。

### 2026-08-09：新增通达信半手动选股闭环

- 决定：暂缓继续扩展外部行情平台，新增“通达信导出 → 系统人工标注 → 后续行情跟踪 → 自动结果/统计/机器学习”的半手动方案；通达信负责执行公式，StratGauge 不解析或执行通达信公式。
- 设计：导出的原始文件按内容寻址保存；导入批次记录选股日期、导出时间、公式名称/版本或哈希、文件哈希和导入人；候选股票全部保留，人工决策与客观行情结果分开存储。
- 时间约束：默认只接受收盘后导入；人工标注必须在首个可执行交易日前冻结；系统使用下一交易日开盘/价格区间、T+1、停牌、费用、止损/目标歧义等既有规则计算结果。
- 机器学习约束：人工标注是决策特征，不直接当作客观胜负标签；结果成熟后才生成标签，按时间切分训练/测试，未成交、过期和未解决不得强行归为输赢。
