# StratGauge 本机任务与验证说明

本文是面向单用户、本机运行的任务补充说明。后端详细输入参数、HTTP API 和行情缓存决策仍以 [`使用文档.md`](使用文档.md) 为准；本文只说明本机任务如何串联、什么时候允许联网，以及如何验收。

## 1. 本机目录边界

默认运行根目录是 `data/`，也可以设置 `STRATGAUGE_DATA_ROOT`。主要目录如下：

| 目录 | 内容 | 是否可作为远程请求替代 |
| --- | --- | --- |
| `data/selection` | 通达信导入、人工标签、客观结果、成熟任务和作业记录 | 只对已有精确批准快照有效 |
| `data/selection-market` | 全市场日线、复权因子、raw、Parquet、manifest、质量报告 | `approved_snapshots` 任务可完全离线 |
| `data/calendars` | 交易日文本和 manifest | 覆盖范围内本地读取；缺口由对应 CLI 决定是否请求远程 |
| `data/universe` | 时间点股票池、证券主数据快照和用户显示覆写 | 只能回答有对应 `as_of/known_at` 证据的历史问题 |
| `data/portfolio` | 手工订单、成交、持仓和复盘 | 不连接券商 |
| `data/jobs` | 本机任务状态和结果摘要 | 不需要 Redis/Celery |

写入共享本机目录的快照、参考证据、股票池、主数据、特征、影子评分和任务账本都有本地锁；重复运行使用内容地址或任务身份幂等，不覆盖已有证据。

## 2. 任务顺序

```text
导入候选
  → 准备交易日历与时间点股票池
  → 同步/核验批准全市场行情
  → （可选）同步批准复权因子
  → 创建 approved_snapshots 成熟任务
  → 本机离线运行成熟任务
  → 从批准行情构建 point-in-time 特征快照
  → shadow 模型评分
  → 人工查看证据；不自动下单、不自动晋升模型
```

成熟任务的 `provider` 是输入证据的一部分，不会自动切换供应商。要离线重放，必须使用已经批准的全市场快照队列；普通 `provider` 模式仍会按任务选择的供应商逐候选请求行情。

## 3. 完整离线成熟命令

先准备一个升序、无重复的本地交易日文件，例如 `sessions.txt`，然后运行：

```powershell
cd D:\Code\Python\StratGauge\backend
$env:PYTHONPATH = "src"
\.venv\Scripts\python.exe scripts\run_offline_maturity_pipeline.py `
  --calendar-file ..\sessions.txt `
  --start-date 2026-01-06 `
  --end-date 2026-01-07 `
  --provider tushare `
  --horizon-sessions 1 `
  --position-notional 10000 `
  --now 2026-01-08T18:00:00+08:00
```

这个命令不会创建任何 provider adapter 请求。它只会：

1. 查找同一 provider、同一时间点股票池、同一交易日且状态为 `approved` 的 `market_daily` 快照；
2. 幂等创建 `approved_snapshots` 成熟任务；
3. 运行任务时只读本地 Parquet 和任务账本；
4. 用禁止远程访问的哨兵适配器防止误拉取；
5. 输出队列结果、job 记录、任务结果和 `SnapshotStore.verify()` 完整性报告。

若缺少快照、快照未批准、股票池不匹配或快照损坏，命令失败或返回非健康验证结果，不会退回逐票 provider 模式。

## 4. 历史特征和离线补数

历史补数 CLI 默认允许选定 provider 远程抓取，但可显式切换为本机模式：

```powershell
\.venv\Scripts\python.exe scripts\backfill_selection_history.py `
  --batch-id <batch_id> `
  --lookback-sessions 21 `
  --sessions-file ..\sessions.txt `
  --provider tushare `
  --offline
```

`--offline` 强制要求 `--sessions-file`，因此不会为了交易日历缺口联网。每个候选、基准和行业目标只复用完全匹配的批准单票快照；命中时报告中的 `access_plan.decision` 为 `cache_hit`，未命中时记录失败，不会请求供应商或自动切换。

## 5. 代码与验证入口

后端：

```powershell
cd backend
$env:PYTHONPATH = "src"
\.venv\Scripts\python.exe -m unittest discover -s tests
\.venv\Scripts\ruff.exe check src tests scripts
\.venv\Scripts\mypy.exe src
```

前端：

```powershell
cd frontend
pnpm typecheck
pnpm build
```

前端 API 边界位于 `src/api/`，入口由 `src/main.tsx` 注入 `ApiClientProvider`；后续页面可以使用 `useApiClient` 或 `useApiResource`，不必在组件内重复拼接 URL、解析错误或管理取消请求。

## 6. 当前边界

- 本机任务调度使用显式 CLI、Windows Task Scheduler 或现有 Web 操作，不引入分布式队列。
- 单票 `provider` 模式是否联网由调用方明确决定；相同 snapshot ID 不代表没有发生过本次远程请求。
- `approved_snapshots` 模式不回退到 provider。
- shadow 评分是独立证据，`used_for_decision` 永远为 `false`；模型晋升仍需要人工评审和比较报告。
- 系统保存交易研究证据，但不连接券商、不自动交易。
